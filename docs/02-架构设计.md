# AI 模型本地安装包系统 —— 架构设计文档

> 版本：v1.0（草案）
> 日期：2026-10-09
> 配套文档：[01-需求设计.md](01-需求设计.md)

---

## 1. 架构总览

系统分为两大子系统，通过 **ModelPack 规范**（模型安装包描述格式）解耦：

```
┌──────────────────────────── 安装框架（打包时） ────────────────────────────┐
│                                                                          │
│  模型来源适配层 → 模型分析器 → 硬件需求估算器 → 配置模板引擎 → 打包器        │
│  (HF/MS/本地/URL)   (架构识别)   (资源需求表)    (ModelPack)   (三平台产物)  │
│                                                                          │
└──────────────────────────────────┬───────────────────────────────────────┘
                                   │ 产出：模型安装包（自包含）
                                   ▼
┌──────────────────────────── 安装包（终端用户机器，运行时） ────────────────┐
│                                                                          │
│  引导安装器 → 硬件探测引擎 → 资源规划器 → 下载管理器 → 运行时层 → 服务层     │
│  (一键入口)    (选最佳GPU)    (量化/卸载)   (断点续传)   (推理引擎)  (API网关) │
│                                                            │             │
│                                            Web 控制台 ←─────┘             │
│                                            (聊天 + 监控 + 设置)            │
└──────────────────────────────────────────────────────────────────────────┘
```

**核心设计原则：**

1. **打包与运行解耦**：框架只在打包时运行；安装包完全自包含，终端用户机器上不需要安装框架。
2. **引擎抽象**：推理引擎（llama.cpp 系 / Strata 式 MoE 引擎 / vLLM）作为可插拔后端，框架按模型架构选择默认引擎。
3. **一切皆清单**：模型的来源、校验、硬件需求、启动参数全部收敛到一份 `modelpack.json`（ModelPack 规范），安装器行为由清单驱动，逻辑通用化、与具体模型无关。
4. **宿主零污染**：所有运行时组件安装在单一应用目录内，可干净卸载。

## 2. 第一部分：安装框架架构

### 2.1 模块划分

```
modelforge/                      # 框架仓库
├── core/
│   ├── sources/                   # 2.2 模型来源适配层
│   ├── analyzer/                  # 2.3 模型分析器
│   ├── estimator/                 # 2.4 硬件需求估算器
│   ├── planner/                   # 资源规划规则库（打包/安装两侧共用）
│   └── modelpack/                 # 2.5 ModelPack 规范（schema + 读写 + 校验）
├── templates/                     # 2.6 配置模板（聊天/代码/多模态/Embedding）
├── builders/                      # 2.7 平台打包器
│   ├── windows/                   #   NSIS exe / 便携 zip
│   ├── linux/                     #   tar.gz + install.sh / AppImage
│   └── macos/                     #   dmg / tar.gz（Apple Silicon）
├── cli/                           # 命令行入口：modelforge build ...
├── gui/                           # 打包者 GUI（Tauri 或 Web 本地版，P2）
└── runtime-bundle/                # 要打进安装包的运行时骨架（见第 3 节）
```

### 2.2 模型来源适配层（sources）

统一接口：

```
interface ModelSource {
    resolve(ref: string) → ModelRef          # 解析用户输入为规范引用
    listFiles(ref) → FileEntry[]             # 文件名、大小、SHA256（如平台提供）
    getMetadata(ref) → RawMetadata           # config.json、模型卡、许可证等
    makeDownloadPlan(ref, variant) → Plan    # 生成下载清单（URL 分片、校验值、镜像候选）
}
```

四个适配器：`LocalDirSource`、`HuggingFaceSource`、`ModelScopeSource`、`DirectUrlSource`。
下载计划只记录"安装时去哪下载"，**打包阶段不搬运权重**（v1.0 不含离线大包）。

### 2.3 模型分析器（analyzer）

输入原始元数据，输出 `ModelProfile`：

| 分析项 | 方法 |
|---|---|
| 架构类型 | 解析 `config.json`（`model_type`、`num_experts`/`n_routed_experts` 判断 MoE） |
| 参数量与激活量 | 权重张量统计；MoE 同时算总参数与单 token 激活参数 |
| 量化支持 | GGUF：直接枚举已有量化变体；Safetensors：标记"需安装时转换或按预置 AWQ/GPTQ 变体" |
| 上下文上限 | `max_position_embeddings` / rope scaling 配置 |
| 能力标签 | 多模态（vision tower 检测）、工具调用、推理（thinking）开关 |
| 许可证 | LICENSE 文件 + 模型卡元数据，打包时强制展示确认 |
| 引擎建议 | 规则引擎：MoE→Strata 式专家缓存引擎；稠密 ≤34B→llama.cpp 后端；稠密大模型高吞吐→vLLM 后端（可选） |

### 2.4 硬件需求估算器（estimator）

对每个量化变体输出资源需求表（这是安装器 P-04/P-05 推荐算法的打包侧来源）：

```
需求(变体) = {
    vram_hot:    热权重显存占用 = 共享层 + 热专家缓存目标容量(VRAM 的 ~85%)
    ram_resident: 内存常驻 = MoE 全量专家池 | 稠密为未卸载层 + KV 预留
    ssd_stream:  低内存模式下需流式读取的量（带显著减速警告）
    disk:        权重文件 + pack + 临时空间（≈ 文件 × 1.3）
    min_ram / recommended_ram
}
```

估算参数来自两部分：**结构化公式**（张量字节数 × 量化位宽系数 + KV cache 公式）+ **实测校准表**（内置类似 Strata 的 12GB/24GB 卡实测数据，误差控制在 15% 内）。

### 2.5 ModelPack 规范（核心契约）

`modelpack.json` —— 框架产出、安装器消费的唯一契约：

```jsonc
{
  "schema": "modelpack/1",
  "name": "qwen3.8-flash-local",        // 打包者输入的安装包名称
  "version": "1.0.0",
  "publisher": { "name": "...", "contact": "..." },
  "model": {
    "family": "qwen3.8-flash-next",
    "architecture": "moe",               // dense | moe | mamba | ...
    "license": "apache-2.0 + qwen-terms",
    "capabilities": ["chat", "vision", "thinking", "tool_use"]
  },
  "variants": [                          // 量化变体（安装器从中推荐）
    { "id": "q2_0",  "size_gb": 44, "quality_rank": 2,
      "requirements": { "min_ram_gb": 32, "vram_hot_gb": 9,  "disk_gb": 60 },
      "sources": [{ "type": "huggingface", "repo": "...", "files": "..." }] },
    { "id": "iq3_s", "size_gb": 58, "quality_rank": 4,
      "requirements": { "min_ram_gb": 64, "vram_hot_gb": 11, "disk_gb": 80 },
      "sources": [ ... ] }
  ],
  "engine": {
    "backend": "strata-moe",             // llama-cpp | strata-moe | vllm
    "version_pin": { "ref": "v0.1.36", "sha256": "..." },   // hash 锁定，可复现
    "defaults": { "context": 65536, "speculative_decode": true,
                  "expert_cache": "auto", "parallel": 1 }
  },
  "service": {
    "port": 8080,                        // 冲突时自动顺延并提示
    "apis": ["openai", "anthropic", "health", "metrics"],
    "lan_exposure": "opt-in-with-key"
  },
  "checksums_sha256": { ... },           // 全包文件清单（含下载清单文件）
  "signature": null                      // 可选 GPG/代码签名
}
```

**这是整个系统最关键的架构决策**：安装器本身是与模型无关的通用程序，所有模型差异都被压缩进清单。新增模型 = 新增一份 ModelPack，不改安装器代码。

### 2.6 配置模板引擎

四类预置模板（聊天/代码/多模态/Embedding）= 预填的 ModelPack 片段 + 引擎参数 + 控制台 UI 配置。打包者选择模板后只需覆盖差异字段。

### 2.7 平台打包器（builders）

| 平台 | 产物 | 技术 |
|---|---|---|
| Windows | `*-setup.exe`（NSIS）+ 便携 zip | NSIS 脚本模板；内嵌引导安装器（Go/Rust 单文件）+ 运行时骨架 |
| Linux | `*.tar.gz`（含 `install.sh`）+ AppImage | tar 打包 + 自解压引导 |
| macOS | `*.dmg` / tar.gz（arm64） | 同上 + Metal 后端 |

打包内容物统一为：

```
<package>/
├── installer(.exe)        # 引导安装器（通用，与模型无关）
├── modelpack.json         # 第 2.5 节的清单
├── runtime/               # 运行时骨架：服务层二进制、Web 控制台静态资源
├── engines/               # 按目标平台预置的引擎二进制（hash-pinned）
└── licenses/              # 引擎与各组件许可证合集
```

### 2.8 框架技术选型

| 组件 | 选型 | 理由 |
|---|---|---|
| 框架 CLI/核心库 | **Python 3.11+**（Typer + Pydantic） | 模型元数据生态全在 Python；ModelPack schema 用 Pydantic 定义即得校验器 |
| 引导安装器 | **Go**（单文件、无依赖、跨平台交叉编译） | 终端机器零依赖；并发下载与系统探测（WMI/`nvidia-smi`/sysfs）成熟 |
| 打包者 GUI（P2） | Tauri + Web 前端 | 复用 Web 控制台技术栈 |
| Windows 安装器壳 | NSIS | 免外部依赖、脚本化、支持静默安装 |

## 3. 第二部分：安装包运行时架构

### 3.1 运行时组件图

```
终端用户机器（单一应用目录，如 %LOCALAPPDATA%\<pkg> 或 ~/.local/share/<pkg>）
│
├── installer            引导安装器：硬件探测 → 资源规划 → 下载 → 组装 → 注册服务
├── agentd               常驻守护进程（服务层）
│   ├── api-gateway      OpenAI / Anthropic 兼容 API、鉴权、限流、请求队列
│   ├── engine-manager   引擎进程生命周期：拉起、健康检查、崩溃重启、参数热更
│   ├── monitor          指标采集：tokens/s、GPU/VRAM/RAM/功耗、上下文占用
│   └── web-console      内嵌静态站点：Chat / Monitor / Settings
├── engines/             推理引擎二进制（llama.cpp 系 / strata-moe / vllm）
├── models/              模型权重与 pack
└── state/               配置、日志、聊天记录（集中一处，卸载即净）
```

### 3.2 关键流程：一键安装（对应需求 P-01 ~ P-06）

```
启动安装器
  │
  ├─ 1. 硬件探测（HardwareProbe）
  │     ├─ GPU 枚举：NVML(nvidia-smi) / ROCm(rocm-smi) / Intel(xpu) / Apple(IORegistry Metal)
  │     ├─ 每卡采集：型号、显存总量/可用、算力代际、当前占用、驱动版本
  │     ├─ RAM 总量/可用、磁盘可用空间、CPU 指令集(AVX2/AVX512)
  │     └─ 失败兜底：无独显 → 明确警告 + CPU 模式（慢速）
  │
  ├─ 2. 最佳选卡（GpuSelector，见 3.3）
  │     └─ 单卡评分排序；多卡时评估聚合显存是否解锁更高档位
  │
  ├─ 3. 资源规划（ResourcePlanner，见 3.4）
  │     ├─ 按 ModelPack.variants × 实测硬件 → 过滤不可行档
  │     ├─ 推荐档位 = 可行档中 quality_rank 最高者（速度警告另附）
  │     ├─ 计算卸载方案：热专家缓存容量 / 层卸载比例 / KV cache 预算
  │     └─ 计算最大可用上下文（用户可调低）
  │
  ├─ 4. 用户确认（≤5 个决策点，全部回车=推荐值）
  │
  ├─ 5. 下载管理器（DownloadManager）
  │     ├─ 分片并发下载 + 断点续传（.part 文件 + 进度账本）
  │     ├─ 每文件 SHA256 校验，失败自动重拉
  │     └─ 镜像故障转移：HF → ModelScope → 自定义镜像
  │
  ├─ 6. 组装与自检：写配置 → 拉起引擎冒烟测试（短 prompt 跑通）→ 失败则降级重试一次
  │
  ├─ 7. 注册服务（可选）→ 打开浏览器 → 完成页显示 API 地址与接入示例
  │
  └─ 幂等性：任何一步中断，重跑安装器从断点继续（状态账本存 state/install-state.json）
```

### 3.3 最佳显卡选择算法（GpuSelector）

```
score(gpu) = 可用显存GB × 1.0
           × 算力系数(代际: Blackwell/Ada=1.2, Ampere=1.0, Turing=0.85; RDNA3=1.0, ...)
           × 空闲系数(1 - 当前显存占用率 × 0.5)
           × 驱动健康系数(驱动版本达标=1, 不达标=0 并提示升级)

选卡规则：
1. 单卡模式：取 score 最高且"可用显存 ≥ 变体 vram_hot 下限"的卡；
   无达标卡时取最高分卡并在资源规划阶段降级变体。
2. 多卡模式：当 Top-N 同代卡聚合可用显存能解锁更高 quality_rank 档位时，
   自动启用多卡切分（层切分/专家切分），默认 N ≤ 4。
3. 用户可用 --gpu 手动覆盖；选择结果与理由写入日志并在控制台展示。
```

### 3.4 显存充分利用机制（吸收并泛化 Strata）

**MoE 模型（strata-moe 后端）—— 三级分布：**

| 层级 | 内容 | 目标 |
|---|---|---|
| VRAM（热） | 共享稠密层 + KV cache + **热专家缓存**（容量 = 可用显存 × 85%） | 路由命中最频繁的专家直接在卡上算，是速度来源 |
| RAM（温） | 全量专家池（pinned memory，异步预取） | 未命中专家从内存取，CPU 并行预计算 |
| SSD（冷） | 大查找表 / 低内存档位的溢出部分（流式读） | 兜底，带显著减速提示 |

引擎侧复用 Strata 的设计（MIT 协议可合法吸收）：专家热度统计驱动的缓存置换、MTP draft 投机解码（1.6~1.8×）、大块 prefill（8192 tokens/批）。**泛化点**：Strata 把这些参数硬编码给单一模型，本系统把"专家数、每 token 激活数、层结构"全部从 ModelPack 读取，由 ResourcePlanner 统一计算。

**稠密模型（llama-cpp / vllm 后端）：**

- 层卸载比例自动调优：`n_gpu_layers = floor(可用显存预算 / 单层显存)`，逐档二分至不 OOM 的最大值；
- KV cache 量化（q8_0/q4_0）按剩余显存自动选择，从而反推可开的最大上下文；
- vLLM 后端（可选）：稠密大模型 + 多并发场景，用 `gpu_memory_utilization` 打到 0.9。

### 3.5 服务层（agentd）

| 模块 | 职责 | 要点 |
|---|---|---|
| api-gateway | `/v1/chat/completions`、`/v1/models`、`/v1/embeddings`、`/v1/messages`（Anthropic）、`/v1/responses`、`/health`、`/metrics` | 协议适配层独立，引擎只暴露统一内部协议；任意 API key/模型名兼容模式（对标 Strata 的"drop-in"体验） |
| engine-manager | 引擎进程拉起/看门狗/崩溃重启/优雅退出 | 参数由 state/config.json 驱动，改配置热重启引擎 |
| monitor | 采样 tokens/s、prefill/decode 分离统计、VRAM/RAM/功耗/PCIe 吞吐、上下文填充率 | WebSocket 推送控制台，对标 Strata Monitor |
| web-console | Chat / Monitor / Settings 三页 | 纯静态资源内嵌 agentd，零前端部署 |
| 鉴权 | 默认绑 127.0.0.1 免 key；绑 0.0.0.0 强制 API Key（启动参数校验，无 key 拒绝绑定） | 安全需求 P-11 的硬约束在 gateway 入口处实现 |

并发模型：默认单请求串行（个人引擎定位，与 Strata 一致），`parallel: 2~4` 可配，UI 明示速度代价。

### 3.6 生命周期管理

| 能力 | 实现 |
|---|---|
| 服务化 | Windows Service（agentd 内建）/ systemd unit 生成 / launchd plist；安装时可选 |
| 更新 | 引擎与模型分离更新；`UPDATE` 入口只拉引擎 diff 与 ModelPack 新版，权重不动；版本 hash-pin 保证可回滚 |
| 卸载 | 应用目录整体删除 + 注销服务 + 清理防火墙规则；**不写注册表系统区、不改 PATH**（P-12） |
| 诊断 | `support-bundle` 一键打包：硬件探测报告、install-state、引擎日志（脱敏） |

## 5. 安全架构

1. **默认最小暴露面**：仅 loopback 监听；局域网模式强制 API Key；不提供任何默认口令。
2. **供应链完整性**：引擎二进制与模型权重全部 SHA256 校验；引擎版本 hash-pin（吸收社区对 Strata "每次启动重新拉二进制"的批评，改为**下载一次、校验、锁定**，更新走显式流程）。
3. **零遥测**：不主动联系任何外部服务器（模型下载源除外）；诊断包由用户显式导出。
4. **许可证合规**：打包时强制确认模型许可证；安装首屏展示；`licenses/` 随包分发。
5. **安装器权限**：默认不需要管理员/root（用户目录安装）；仅"注册系统服务"一步按需提权并明示。

## 6. 可扩展性设计

| 扩展点 | 机制 |
|---|---|
| 新模型 | 写 ModelPack（框架自动生成 90%，人工校准 10%） |
| 新引擎后端 | 实现 `EngineAdapter`（start/stop/health/内部推理协议），注册进框架引擎表 |
| 新硬件平台 | 实现 `GpuProbe` 插件（枚举 + 评分参数表） |
| 新量化格式 | 在 analyzer 注册格式解析器 + estimator 注册位宽系数 |
| 新协议 | api-gateway 内新增协议适配器（如未来 OpenAI 新接口） |

## 7. 技术风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| AMD/Intel 引擎路径不成熟 | 部分用户安装失败或极慢 | 架构上引擎可插拔；v1.0 标注实验性；探测阶段驱动不达标则明确劝阻 |
| Strata 上游许可证/方向变化 | MoE 后端维护成本 | 只依赖其 MIT 代码与公开格式，fork 保底；稠密场景以 llama.cpp 为主路径，不单点依赖 |
| 估算与实际资源占用偏差 | 推荐档位 OOM | 安装冒烟自检 + 失败自动降档重试；实测校准表随版本迭代 |
| 70GB+ 下载体验 | 安装中断流失 | 分片断点续传 + 国内镜像 + 明确的进度与剩余时间展示 |
